# Adaptive Differential Evolution architecture

v0.12.0 creates the architecture shared by the adaptive DE family without hiding all
variants inside one monolithic optimizer.

## Scientific lineage

### jDE-style self adaptation

Brest, Greiner, Boskovic, Mernik and Zumer (2006):
"Self-Adapting Control Parameters in Differential Evolution: A Comparative Study on
Numerical Benchmark Problems",
IEEE Transactions on Evolutionary Computation 10(6), 646-657.
DOI: 10.1109/TEVC.2006.872133.

Architectural requirement:
persistent per-individual control parameters with trial values committed on successful
selection.

### JADE

Zhang and Sanderson (2009):
"JADE: Adaptive Differential Evolution With Optional External Archive",
IEEE Transactions on Evolutionary Computation 13(5), 945-958.
DOI: 10.1109/TEVC.2009.2014613.

Architectural requirements:
- current-to-pbest mutation;
- optional external archive;
- adaptive control-parameter generation from evolving means.

### SHADE

Tanabe and Fukunaga (2013):
"Success-History Based Parameter Adaptation for Differential Evolution",
IEEE CEC 2013, 71-78.
DOI: 10.1109/CEC.2013.6557555.

Architectural requirement:
historical memory of successful F/CR settings rather than only current running means.

### L-SHADE

Tanabe and Fukunaga (2014):
"Improving the Search Performance of SHADE Using Linear Population Size Reduction",
IEEE CEC 2014, 1658-1665.
DOI: 10.1109/CEC.2014.6900380.

Architectural requirement:
SHADE plus population-size reduction driven by consumed function evaluations.

## Component model

```text
Adaptive DE engine
   |
   +-- mutation / guide selection
   |      +-- rand/1
   |      +-- current-to-pbest/1
   |
   +-- parameter adaptation
   |      +-- Fixed
   |      +-- jDE
   |      +-- JADE mean adaptation
   |      +-- SHADE success-history memory
   |
   +-- external archive
   |      +-- none
   |      +-- flat vector archive
   |
   +-- population schedule
          +-- constant
          +-- linear reduction
```

## Why bulk parameter policies

`IDeParameterAdaptationPolicy` operates once per generation rather than once per
dimension.

This keeps strategy polymorphism outside the innermost component loop and lets the
specialized DE engine continue to fuse mutation and crossover.

## Parameter buffers

`DeParameterBuffers` stores:

```text
parent F
parent CR
trial F
trial CR
```

This directly supports the jDE rule that unsuccessful trial parameters must not replace
the inherited per-individual parameters.

The same buffers can also hold the sampled parameters generated by JADE/SHADE before
variation.

## External archive ownership

`DeExternalArchive` stores vectors in one flat owned array.

Input vectors are copied, not aliased.

When full, an incoming vector is treated exactly as if it were appended and then one
of `Capacity + 1` vectors were removed uniformly at random, without allocating an
extra temporary slot.

## L-SHADE population schedule

`LinearDePopulationSizeReductionPolicy` exposes the evaluation-budget-driven linear
schedule independently of the engine.

The engine integration in a later release will decide which worst individuals are
removed and will synchronize archive capacity accordingly.
